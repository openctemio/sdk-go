### Added: detect.services conformance suite with a credential sentinel

- `pkg/conformance`: the capability suite of `detect.services@1`. Seven loopback fixtures (SSH, Redis that requires a password, a MySQL greeting, SMTP with a hostile multi-line greeting, plain HTTP, HTTPS with ALPN h2 and http/1.1, LDAP) run as service targets with `depth: thorough`. Each fixture is a credential sentinel: any SSH user authentication (none, password, public key, keyboard-interactive), a MySQL handshake response, a Redis `AUTH` or `HELLO ... AUTH`, an SMTP `AUTH`, `MAIL`, `RCPT` or `DATA`, an LDAP bind, an HTTP `Authorization` or `Proxy-Authorization` header or a state-changing HTTP method fails the suite.
- The suite also checks the report: services keep the value of their input port, the six protocols are identified (TLS on the HTTPS fixture), the Redis fixture is never reported as anonymous, and strings are bounded and clean (banner at most 512 bytes of valid UTF-8 without control characters, at most 16 details of at most 256 bytes).
- `RunContractSuite` runs it for an exec tool that implements `detect.services@1`; a tool compiled into a sensor calls `DetectServicesSuite` with a function that runs it (for example with `pkg/testkit`). `StartServiceFixtures` exposes the fixtures for a tool's own tests.
